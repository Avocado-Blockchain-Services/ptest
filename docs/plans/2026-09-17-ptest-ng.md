# ptest NG Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement the assigned task. The root orchestrator coordinates the already-approved parallel workflow; do not spawn agents or choose a different model yourself. Steps use checkboxes for execution tracking in your task report, not edits to this shared plan.

**Goal:** Replace legacy cloud-first ptest with an honest, bounded, local-first test coordinator, conservative selector, and suite doctor.

**Architecture:** One account-local transactional scheduler admits short-lived process-group guards. Native runner bridges preserve output/configuration/coverage and produce bounded evidence; explicit file groups and durable failures drive conservative selection. Static diagnosis and generic instructions remain separate from authorized execution.

**Tech Stack:** CPython3.11–3.14, stdlib SQLite/TOML/JSON, psutil7.2.2, uv/setuptools, a shipped Node bridge, pinned pytest9.1.1/xdist3.8.0 and Vitest3.2.7 acceptance profiles.

**Spec:** [Approved product](../specs/2026-09-17-ptest-ng-product.md), [frozen design and contracts](../designs/2026-09-17-ptest-ng-design.md), and runner/scheduler/interoperability research in `docs/research/`.

## Global constraints

- Product runtime requires no model API, cloud credentials, hosted service, native TUI integration, or mandatory optional pytest plugin.
- Linux/macOS are the accepted target platforms; unavailable macOS evidence is an unpassed release gate, never a simulated pass.
- All tests go through `ptest`; no raw pytest/vitest/npm test/go test/cargo test commands, including verification helpers. Dependencies use uv, not pip. Never share `.venv`/`node_modules` between worktrees.
- During tasks use scoped tests only. The root owns one final integrated `ptest --full` after implementation and repairs; if that run fails and changes follow, rerun the required final gate and retain both attempts.
- Normal scheduler identity is independent of HOME/XDG/TUI/cwd/install. Fixture-domain use is explicit, private, root-contained, labeled, and restricted to bounded test workloads.
- Source/expectation changes during automatic/full execution cannot produce a green final gate. Arbitrary argv is withheld from default owned output, while literal child arguments and stdout/stderr are preserved.
- No push, main merge, live CLI replacement, cloud operation, real-service migration, publication, source upload, or native TUI/trust changes. Local package/test dependency setup and declared advisory metadata requests are implementation steps; report them.
- Every task owns a separate worktree under `/home/ingmar/worktrees/ptest/cx-ng-product/`; no writer reverts another task. Root integrates reviewed commits onto the chain only.
- `contracts.py` and its generated schema descriptors are the one shared authority. No worker invents another public signature or edits another task's registration point. Escalate contract changes before coding consumers.
- The provisional `cx-ng-foundation/ptest` is read-only candidate reuse. Copying its dirty source wholesale is not approved.

## Workflow, files, and the runnable barrier

Root reads the actual Dan role and Muse CLI reference, supplies `.pipeline/briefs/muse-dan-common.md`, and launches the actual requested Muse model with medium effort in each existing task worktree. Muse receives this task's section, the complete contract design, security/TDD instructions, and its owned report path `.pipeline/out/task-N.json`. Opus reviews each completed task/wave and its red/green evidence; no silent substitution if a requested model is unavailable. Root does not write feature code. Integrated Opus audit then independent Astra audit are mandatory; Sol handles any subsequent corrective implementation.

Every task report records owned/touched files, source SHA, commands/cwd/exit/raw evidence paths, red assertion, green result, applicable A/security IDs, three Dan passes, discovered debt, unverified items, and claimed-versus-shipped delta. Reports are uniquely owned, not shared. Each source-changing worktree runs `graphify update .` without semantic extraction; absence/tool failure is recorded, not hidden. Reviewers follow audit-spec. No task reports a failure pre-existing without the same command on the named baseline and equivalence evidence.

Task0 is the only bootstrap/contract writer. Before parallelization it supplies an executable development wrapper `scripts/ptest-bootstrap` which calls the **already installed** legacy ptest by a frozen absolute path, with a generated private local-only config and one worker. That wrapper is not a new test runner. Required legacy facts verified in source: `PTEST_CONFIG` is honored, configured project `scoped`/`full` command strings are supported, `--local` prevents routing, and workers1 injects `-p no:xdist`. It must never resolve a subsequently changed PATH command as its bootstrap.

Bootstrap config generated for each worktree (not committed machine-specific config):

```toml
[defaults]
workers = 1
[projects.ng_bootstrap]
root = "/absolute/git-common-dir-parent"
kind = "pytest"
backend = "local"
workers = 1
scoped = "uv run --locked --no-sync python -m pytest"
full = "uv run --locked --no-sync python -m pytest"
```

The helper obtains the original common-dir parent with Git argv, safely quotes it as TOML, writes under private `.pipeline/local/`, and invokes frozen legacy ptest with `PTEST_CONFIG` and `--local`. It only accepts scoped arguments until the root's final-gate switch; it prints the resolved dispatcher/config provenance, not secrets. Initial T0 dependency resolution (`uv sync`) is allowed only after the design gate; commit uv.lock, then all subsequent task worktrees use `uv sync --locked`. Package entrypoint is new and local; root extensionless legacy `ptest` is not replaced until T13.

Runnable barrier commands, after T0 creates its initial manifest/lock and test:

```bash
export PTEST_BOOTSTRAP="$(command -v ptest)"
uv sync --locked

```

`where` must show the current worktree and explicit local backend/one worker. Store the resolved legacy target/version/config hash in the task report. A deliberate failing assertion must produce nonzero before accepting bootstrap. Never fall back to raw runners if this fails. If the installed legacy bundle is unavailable or changed, stop the implementation gate and ask the root to restore the approved bootstrap, not install over it.

### Frozen test-helper interface (Task0 owns)

`tests/ng/conftest.py` provides `case: CaseFactory`; implementation in `tests/ng/support.py` stays test-only. `case.config(**overrides) -> Config`, `case.snapshot(**overrides) -> InputSnapshot`, `case.history(**overrides) -> HistoryView`, `case.request(**overrides) -> RunRequest`, `case.result(**overrides) -> RunResult`, `case.inventory(files: tuple[str,...], **overrides) -> Inventory`, and `case.checkout() -> CheckoutIdentity` return valid typed fixtures with explicit override validation. `case.domain(slots=1,jobs=1) -> DomainPaths` creates a private fixture tree/marker. `case.project(domain, kind="command") -> Path` creates an initialized miniature project within it. `case.invoke(domain, root, *args, env=None, timeout=10) -> Completed` invokes the exact candidate interpreter/entrypoint, explicitly passes fixture-domain, clears bootstrap-only PTEST_CONFIG and stale marker env, captures bytes with a bounded watchdog, and returns `Completed(code:int, stdout:bytes, stderr:bytes, result:dict|None)`. No helper silently invokes an application suite. `case.barrier(name)` is owned pipe-based synchronization; `case.events(domain)` reads bounded fixture transition events. Task0 supplies the general helper; later tasks add **their own local helpers**, never edit shared conftest/support concurrently.

For the examples below, config helper aliases are exactly `runner_kind`→runner.kind, `workers`→runner.workers, `selection_enabled`→selection.enabled, `closed_inputs`→selection.closed_inputs; history helper `with_baseline=True` creates a compatible complete baseline; inventory helper `outcome` populates each TestRecord; result helper `sequence` sets the design's internal admitted sequence. Other overrides name actual record fields. Unknown aliases raise, not silently ignored. `case.invoke` requests a unique project-relative result export by default unless the caller supplies one, then parses that file if produced; startup errors may leave result=None. Its environment cleanup removes only documented inherited ptest/bootstrap control variables, not arbitrary test sentinels. Concurrency fixtures declare known tiny memory estimates so unknown-memory serialization does not make admission tests vacuous.

Schema export tool `scripts/export-schemas.py` imports only contracts, emits deterministic JSON Schema from descriptors and checks drift with `--check`. Bootstrap contracts tests can run without any scheduler/runner installed. Shared scaffolding must be functional, not NotImplemented stubs advertised as features.
