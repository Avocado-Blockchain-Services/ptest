**Goal:** Build brand-new ptest NG as an honest, bounded, local-first test coordinator, conservative selector, and suite doctor; remove the old production runtime at final repository cutover.

**Scope amendment (2026-09-18):** User-directed clean break. No shipped legacy compatibility, migration, global project configuration, cloud/remote routing, or old-command execution surface. ## Global constraints

- Product runtime uses only the nearest project’s versioned `.ptest.toml` plus the fixed host scheduling limits and NG-owned state in design§7. No discovery, parsing, conversion, adoption, warning, or execution of legacy global config, registrations, command strings, aliases, `also_roots`, environment redirects, old history, cloud credentials, remote backends, or remote-only fields.
- Product runtime requires no model API, hosted service, native TUI integration, or mandatory optional pytest plugin. Static init/register/doctor/where/plan execute no repository code, package manager, dependency lifecycle, hook, network request, or shell string. Setup remains visible; authorization means a reviewed, committed setup declaration plus an explicitly executing ptest run. `--no-setup` is the per-run opt-out; no additional opt-in flag is required.
- Linux/macOS are the accepted target platforms; unavailable macOS evidence is an unpassed release gate, never a simulated pass.
- All tests go through `ptest`; no raw pytest/vitest/npm test/go test/cargo test commands, including verification helpers. Dependencies use uv, not pip. Never share `.venv`/`node_modules` between worktrees.
- During tasks use scoped tests only. The root owns one final integrated `ptest --full` after implementation and repairs; if that run fails and changes follow, rerun the required final gate and retain both attempts.
- Normal scheduler identity is independent of HOME/XDG/TUI/cwd/install. Fixture-domain use is explicit, private, root-contained, labeled, and restricted to bounded test workloads.
- Source/expectation changes during automatic/full execution cannot produce a green final gate. Arbitrary argv is withheld from default owned output, while literal child arguments and stdout/stderr are preserved.
- No push, main merge, live CLI replacement, cloud operation, real-service migration, publication, source upload, or native TUI/trust changes. Local package/test dependency setup and declared advisory metadata requests are implementation steps; report them.
- Every task owns a separate worktree under `/home/ingmar/worktrees/ptest/cx-ng-product/`; no writer reverts another task. Root integrates reviewed commits onto the chain only.
- `contracts.py` and its generated schema descriptors are the one shared authority. No worker invents another public signature or edits another task's registration point. Escalate contract changes before coding consumers.
- The provisional `cx-ng-foundation/ptest` is read-only candidate reuse. Copying its dirty source wholesale is not approved.

### Frozen test-helper interface (Task0 owns)

`tests/ng/conftest.py` provides `case: CaseFactory`; implementation in `tests/ng/support.py` stays test-only. `case.config(**overrides) -> Config`, `case.snapshot(**overrides) -> InputSnapshot`, `case.history(**overrides) -> HistoryView`, `case.request(**overrides) -> RunRequest`, `case.result(**overrides) -> RunResult`, `case.inventory(files: tuple[str,...], **overrides) -> Inventory`, and `case.checkout(domain: DomainPaths) -> CheckoutIdentity` return valid typed fixtures with explicit override validation. `case.domain(slots=1,jobs=1) -> DomainPaths` creates a private fixture tree/marker using T0's files primitives, without importing T2 platform or resolving normal state. `case.project(domain, kind="command") -> Path` creates an initialized miniature project within it. `case.invoke(domain, root, *args, env=None, timeout: float) -> Completed` requires an explicit keyword watchdog and invokes the exact candidate interpreter/entrypoint, explicitly passes fixture-domain, clears stale NG marker env, captures bounded bytes, and returns `Completed(code:int, stdout:bytes, stderr:bytes, result:dict|None)`. Use10s for tiny CLI cases,45s for30s recovery, and an explicitly justified phase deadline plus10s for probe/shadow/setup; test fake clocks for long policy timeouts rather than sleep minutes. No helper silently invokes an application suite. `case.barrier(name)` is owned pipe-based synchronization; `case.events(domain)` reads bounded fixture transition events. Task0 supplies the general helper; later tasks add **their own local helpers**, never edit shared conftest/support concurrently.

For the examples below, config helper aliases are exactly `runner_kind`→runner.kind, `workers`→runner.workers, `selection_enabled`→selection.enabled, `closed_inputs`→selection.closed_inputs; history helper `with_baseline=True` creates a compatible complete baseline; inventory helper `outcome` populates each TestRecord; result helper `sequence` sets the design's internal admitted sequence. Other overrides name actual record fields. Unknown aliases raise, not silently ignored. `case.invoke` requests a unique project-relative result export by default unless the caller supplies one in the recognized ptest prefix, then parses that file if produced; startup errors may leave result=None. Result-export detection follows design§4: `--fresh` and `--local` start the untouched runner tail, so a later `--result-json` is runner data, not a ptest export. Default cleanup removes documented stale NG control markers, not arbitrary test sentinels; existing legacy redirect entries in `CONTROL_VARS`, including `PTEST_CONFIG`, are retained only as temporary bootstrap hygiene until T13. Explicit `env=` overrides are applied after cleanup and must reach the child unchanged. Legacy redirect variables deliberately remain in dedicated tests, including the Python test process, to prove native resolution never reads their targets or emits legacy warnings/errors. Environment scrubbing is not required for NG correctness; T13 removes bootstrap-specific test hygiene, not the helper grammar/wording repairs already required at T0. Default concurrency fixtures retain memory estimate0/unknown and no machine memory budget; separate opt-in accounting fixtures declare explicit estimates, without claiming they are measurements.

Schema export tool `scripts/export-schemas.py` imports only contracts, emits deterministic JSON Schema from descriptors and checks drift with `--check`. Bootstrap contracts tests can run without any scheduler/runner installed. Shared scaffolding must be functional, not NotImplemented stubs advertised as features.
