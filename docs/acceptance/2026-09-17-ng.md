# ptest NG acceptance evidence

This page describes the reproducible local acceptance harness. It is an
evidence format and operator runbook, not a release claim. The harness is
invoked directly, outside an active `ptest` run, so it cannot become a nested
normal-domain test.

## Local bounded smoke

From a checkout with the candidate executable available:

```sh
python scripts/acceptance.py --root "$PWD" --ptest /absolute/path/to/ptest \
  --output /tmp/ptest-acceptance-evidence --execute
```

The command uses literal argv, validates the candidate's semantic version and
SHA-256 identity, creates an owned 0700 fixture domain with the runtime's
`fixture-domain.toml` marker and two nested miniature projects, then records
init/where/plan/doctor/status/full/scoped/automatic lifecycle attempts. It
applies a finite timeout, captures stdout/stderr, and retains failed or capped
attempts. `--execute` is opt-in. Without it the command records an
inventory-only result and cannot promote support. A version-only or generic
exit-zero executable is never promotable.

The benchmark CLI is intentionally narrower: it requires the exact candidate
`ptest --version` argv and the declared workload profile. Raw `/bin/sh`,
pytest, npm, and other native runner commands are rejected before a child is
started.

The JSON artifact records the candidate path, commit/config digest, platform,
command, setup and network requirements, status, exit code, duration, and raw
artifact directory. A non-zero result means evidence is incomplete or failed;
it is never converted into a passing claim.

Every evidence root is created exclusively with mode `0700`; existing files,
directories, symlinked leaves, and symlinked parents are refused. Each retained
stdout/stderr/JSON artifact is created exclusively with mode `0600`. Reusing an
evidence root is refused so a second invocation cannot mix samples from two
candidates.

## Independent adoption

The approved candidates are apispec at
`bfac55c9bfbc4edbdde505d29d8c20c62133fc10` and tailwind-merge at
`71218a58edc9e5ad36e5a3233b51c893782a411d`. No checkout, package installation,
Yarn lifecycle, or network operation is performed automatically by this
repository. Until an operator authorizes and records those runs, both remain
`blocked-unverified`; miniature fixtures do not substitute for adoption.

Advanced selection, baseline, cross-platform, and performance claims require
their corresponding real evidence. Linux-only local output does not establish
macOS support.
