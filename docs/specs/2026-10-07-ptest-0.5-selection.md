# Spec: ptest 0.5 — dependency-recorded test selection

Date: 2026-10-07. Status: user-directed ("take us to 0.5 with a way better test
selection algorithm; must be very good"). Copy into the branch as
`docs/specs/2026-10-07-ptest-0.5-selection.md`. Pytest only; Vitest unchanged.

## 1. Problem and evidence

Bare `ptest` / `--changed` / `--base` select tests with a static reverse-import
graph (`src/ptest/impact.py`). It answers "which test files could *import* the
changed file", not "which tests *run* the changed code".

Measured on 2026-10-07 in `persea_content_maker_unified/api` (716 test files,
about 12.6k tests, full suite 18–25 min with xdist and coverage), for a change to
`editorial_pipeline/service.py`:

- The 0.4.10 planner reaches 559 of 716 test files, crosses `full_ratio 0.7`, and
  runs the whole suite. Only 37 test files import the module directly, and 84
  mention the package at all.
- The reach comes from two hubs: `editorial_pipeline/__init__.py` re-exports from
  `service`, so importing *anything* from the package marks `service.py` as
  loaded; and the app factory imports every router.
- Planning alone took 29.3 s. It re-reads and re-parses every `.py` file twice,
  on every run.
- The planner is also incomplete in the other direction. A module imported only
  through a `conftest.py` fixture is never connected to the tests that use the
  fixture.

The result: agent pipelines ran the full suite after every edit, every gate and
every fix round. Nothing converged ("this is insane, it will never be over").

Prototype evidence (section 12) quantifies how many tests actually execute a
given function, compared with the static selection.

## 2. Goals

G1. **Select tests by what they ran.** A test reruns when code or data it
    depended on, the last time it passed, has changed. Reaching the change in
    the import graph is not enough. Granularity is the function for code, the
    statement or name for module-level code, and the file for data. Selection is
    at the test node id, not the test file.
G2. **Fail safe, per test.** Whenever a test's dependencies are unknown or
    unprovable, that test falls back to the 0.4 static rule (made sound for
    conftest reach). Whenever the whole picture is unknown, the run falls back to
    full. Falling back is never an error.
G3. **Cheap enough to be always on.** Recording runs on every pytest run (full,
    scoped, changed) with a bounded overhead. Planning reuses a per-file parse
    cache and is fast (targets in section 10).
G4. **Self-auditing.** Every full run checks whether the selector would have
    missed any test that failed. Misses are reported, and the affected tests are
    demoted to the static rule, so the selector learns instead of silently
    repeating a miss.
G5. **Shared across a project's checkouts.** A builder worktree's records serve
    the gate worktree on the same code. When nothing a test depended on changed
    since it passed, the result is "no tests affected" without running anything,
    including under `--base dev`.
G6. **Explainable.** The start line states engine, test count, file count and
    the main changed units. `-v` explains each selection reason and each
    fallback.
G7. **Proven.** A committed evaluation harness measures safety (mutation
    testing) and precision against 0.4.10 on real suites. The release ships only
    if section 10's thresholds hold.

## 3. Non-goals

- Vitest selection (it keeps `vitest --changed` delegation).
- Replacing the full gate. Changed-mode green stays iteration-only; only
  `ptest --full` completes a change. The agent rules keep saying so.
- The advanced closed-inputs, groups and shadow path in `selection.py`. It is
  untouched.
- Predictive or ML selection, test prioritisation, and cross-machine record
  sharing.
- Python < 3.12 in the *test process*. Those projects keep the 0.4 static
  planner (with the conftest fix and the parse cache).

## 4. Model

Regression test selection against each test's last passing record, the
Ekstazi-style safe-RTS criterion extended to Python. If no dependency of test T
changed since T last passed, T's execution trace is identical (under
determinism, see section 9's residual risks), so it passes again and is skipped.
Otherwise T is selected.

Dependencies of T, recorded in the test process:

| Kind | Meaning | Recorded how |
|---|---|---|
| F(T) | project functions whose body executed in T's context | `sys.monitoring` PY_START |
| M(T) | project module bodies executed in T's context (lazy imports) | PY_START on `<module>` code |
| X(T) | higher-scope (class/module/package/session) fixtures T uses; their own deps are recorded in fixture context | pytest fixture closure + fixture-setup context |
| D(T) | project data files (non-`.py`) opened in T's context | audit hook `open` |
| opaque(T) | T or one of its fixtures spawned a process that can run project Python (python/uv/pytest/ptest/the venv's executables/a script in the checkout), or forked, or recording failed or overflowed | audit hooks `subprocess.Popen`, `os.posix_spawn`, `os.exec`, `os.spawn`, `os.system`, `os.fork` |
| outcome(T) | worst phase outcome of the run that wrote the record | bridge report |

**Ambient context**: everything executed outside a test or fixture context
(imports at collection, conftest import, collection hooks, session teardown).
Functions and data executed there are *ambient*; module skeletons are always
ambient.

**Source index** (per file content, cached): module names, import edges, the
scope table (each function or method by qualname: an AST-normalised body
fingerprint plus a skeleton fingerprint of decorators, signature, defaults and
returns), the top-level statement table (per statement: kind, bound names,
resolved name references, effectful flag, fingerprint), class-body statements,
and per-function resolved references to module-level names. Fingerprints use
`ast.dump(..., include_attributes=False)`, so comments, whitespace and line
shifts never count as changes.

## 5. Planner v2 decision procedure (bare / `--changed` / `--base` / folder changed runs)

Inputs: the current input snapshot (per-file digests), the project dependency
store (section 6), and the current source index.

1. **Engine gate.** Use the static planner (0.4 rules plus section 5.9) and
   name the reason when any of these hold: the store is missing, unreadable or
   incompatible (compatibility fingerprint, selection policy digest, Python
   minor, platform); `[selection] dynamic = false`; selection is disabled; the
   runner is not pytest.
2. **Full triggers** behave as today: configured `full_triggers`,
   `.ptest.toml`, lockfiles and manifests, `conftest.py`, pytest config files.
3. **Changed units.** For each project file whose current digest differs from a
   digest referenced by any record, diff its recorded scope table (looked up by
   digest) against the current one:
   - function body changed or function removed → the function changed;
   - function skeleton changed (decorator, signature, defaults) → the function
     changed, *and* its name changed;
   - class-body statement changed (not a method body) → the class name changed,
     and every method of the class counts as changed for F-matching;
   - top-level definition changed (def/class/import/assign/annassign/augassign)
     → its bound names changed;
   - effectful top-level statement changed (expression call, if/for/while/with/
     try/match, delete, global, assert, or anything unclassified) → **ambient
     change** of that module;
   - new functions or classes in a test file → that whole test file is selected.
4. **Name propagation** to a fixpoint across the current index:
   - a function body that references a changed name (resolved through import
     aliases, `module.attr`, and re-export chains in `__init__`) → that
     function is affected;
   - a definition statement whose skeleton references a changed name → its
     bound names change (subclasses, decorators, defaults, module constants);
   - an effectful statement that references a changed name → ambient change of
     its module;
   - `from M import *` binds every public name of M (conservative); an
     unresolvable or dynamic reference is not tracked (residual R2).
5. **Per-test selection.** T is selected if any of these holds:
   - its last outcome was not passed, skipped or xfailed;
   - F(T) contains a changed or affected function; or a function in X(T)'s
     fixture records does;
   - M(T) contains a module with a skeleton change;
   - D(T), or a fixture in X(T), opened a changed or deleted data file;
   - T is opaque or demoted (section 7) and its test file statically reaches a
     changed file, or any data file changed;
   - its test file was added or changed in a way that is not a body change of
     recorded tests.
6. **Ambient changes.** A body change to an ambient function, an ambient change
   of a module, or a change to an ambient data file → every test whose file
   statically reaches that module or file (5.9), or full when the data file has
   no static anchor.
7. **Unrecorded tests.** A test file on disk with no records (new, or never run
   under 0.5) → the static rule decides for that file. A recorded file with
   unknown node ids (new parametrisation) → those ids run (section 6.3
   deselect-list semantics).
8. **Output.** The selected node ids grouped by file, plus whole files. When
   nothing is selected: "no tests affected", with the count of tests that reach
   the change but already passed on this code.
9. **Static rule (fallback and pre-0.5 engine).** The 0.4 reverse-import
   closure, plus an edge from every `conftest.py` to the test files under its
   directory (fixes the conftest soundness gap), and served from the parse
   cache. `full_ratio` and the 200-file scoped limit keep applying *only* to
   static selections. A dynamic selection runs at node-id granularity with no
   ratio cut-off, but a dynamic selection of at least `full_ratio` of all tests
   runs as `--full`, so it can still record a reusable full proof.

## 6. Components

### 6.1 Bridge recorder (`runtime/pytest_bridge.py`, stdlib-only)

- **Activation.** On by default for pytest runs when the test process has
  Python ≥ 3.12 and `[selection] dynamic` is not false. It registers a
  `sys.monitoring` tool (the first free id among 3, 4 and 2; if none is free it
  does not record and says why) and one audit hook.
- **Tracing strategy (prototype-backed, section 12).** No *global* monitoring
  events. PY_START is enabled with `set_local_events` only on project code
  objects. They are discovered when their module executes, through the audit
  `exec` event that every import raises with the module code object (walk
  `co_consts` recursively), plus one `sys.modules` walk at activation for
  modules imported earlier. The callback stores the code object in the current
  context's set and returns `DISABLE`. Every context switch calls
  `restart_events()`, which then re-fires only project code (and other tools'
  disabled events), never library code. Measured: 3–7× cheaper than global
  events with restart, and correct, whereas re-arming with `set_local_events`
  alone does *not* clear DISABLE. A callback on every call costs 3–5× and is
  rejected. Code objects are converted to `(relpath, qualname, firstlineno)`
  at context end, keeping only regular files inside the checkout and outside
  venv, site-packages and caches. The `exec` event in a test context also
  records M(T) (a lazy import).
- **Per-test overhead budget.** Recording must not push tests over per-test
  limits. Persea suites use `pytest-timeout` at 1 s, and the prototype, with
  global events on a loaded machine, tripped six of them. The A4 benchmark
  reports per-test p95 overhead (target ≤ 5 ms) next to wall time.
- **Contexts.** A test context covers setup, call and teardown, including
  function-scoped fixtures. A higher-scope fixture setup gets its own context
  keyed by `(baseid, argname, scope)`, and the test records that it uses the
  key. Everything else is ambient.
- **Audit hook.** `open` events record data paths inside the checkout,
  excluding `.py`, `.pyc`, `__pycache__`, `.git` and output dirs. Spawn events
  mark the context opaque unless the executable resolves to a binary outside
  the checkout and outside the project venv and is not a Python, uv, pytest or
  ptest launcher. `os.fork` and `os.system` always mark it opaque. The hook
  must never raise, and is a no-op when not recording.
- **Output.** One dependency file per process, next to the bound native
  report, in the private reports dir: name derived from the report name plus
  the pid, O_EXCL|O_NOFOLLOW, mode 0600, the same rules as the 0.4.10 stack
  dumps. Bounded: per-context function and data caps (overflow → opaque) and a
  per-file byte cap (overflow → that worker's records are dropped and the
  report notes it). Written at session end. A worker that crashes leaves no
  file, so its tests stay unrecorded.
- **No behaviour change.** Literal argv, outputs and exit codes, coverage
  results and pytest's own faulthandler or monitoring users are untouched. If
  recording fails, the run continues unrecorded.

### 6.2 Source index and parse cache

- One parse per file content (keyed by keyed digest), cached in the store. A
  planning run re-parses only files whose digest is not cached. It replaces
  the double read and parse in `impact.plan` for both engines.
- Bounded: `MAX_SCAN_FILES` and `MAX_FILE_BYTES` keep applying. Files that
  can't be parsed become a reason, as today.

### 6.3 Dependency store (per project id, shared by its checkouts)

- Location: the state domain, `projects/<project_id>/selection.db` (SQLite),
  private (0700 dir, 0600 file). It uses the existing SQLite open, hot-journal
  recovery and corruption-handling rules. It is never read by older ptest; the
  history store and persisted summaries are unchanged (N9).
- Content:
  - file versions: digest → scope table, statement table and index blob;
  - test records: node id → test file, outcome, run id, recorded at,
    compatibility fingerprint, opaque flag, demoted flag, then per file
    `(path, recorded digest, executed qualnames, module-body flag)`, data files
    `(path, keyed digest)`, and fixture keys;
  - fixture records;
  - ambient sets;
  - audit counters.
- **Updates** only from runs whose protocol handoff was valid and whose inputs
  did not change during the run. Only the tests that ran are replaced; every
  other record is kept. Each update is one transaction.
- Concurrency safe across checkouts and runs.
- **Pruning.** Drop node ids absent from the last two full inventories, and
  file versions no record references. Hard cap on size (section 10). Over the
  cap, drop the oldest records, which then fall back to static.
- **Never stored:** file contents, function source, or unkeyed content hashes
  of untracked or ignored files (keyed MACs, as `source.py` already does).
- `ptest uninstall` removes it. `ptest status` / `-v` show its size and record
  count.

### 6.4 Narrowed execution

- argv is the selected test files, as today, so literal argv semantics are
  kept.
- Within partially selected files, the bridge deselects exactly the *recorded,
  not selected* node ids. It reads them from a private binding file (path in
  the environment, validated like the report binding). Unknown node ids
  therefore always run.
- Deselected tests are reported as such and never counted as passed.
- Counts and the end line report the tests run.

### 6.5 Self-audit on full runs

At the end of a valid full run, plan against the store as it was *before* this
run's updates and the run's input snapshot. Every test that failed in the full
run, whose prior record was passed, and that the plan would not have selected,
is a **miss**. Misses:

- print `ptest: selection audit: N failing tests would not have been selected
  — they now run whenever a change statically reaches them`;
- demote those tests (static rule);
- increment audit counters.

`-v` prints the audit summary even when there are no misses. A demotion clears
when the test's own file content changes.

### 6.6 UX and docs

- Start line examples:
  - `changed: api/src/…/service.py (+1 file) → 214 tests in 31 of 716 files
    (dynamic · 3 functions changed)`
  - `→ no tests affected: 214 tests reach these changes and already passed on
    this code`
  - `→ 559 of 716 test files (static: no dependency records yet — any run
    records them)`
- `-v` lists:
  - changed units: function, name or module, data file, each with its test
    count;
  - fallbacks and their reasons;
  - store age and coverage, i.e. the share of current tests recorded.
- Docs:
  - update `docs/ptest-agent.md`, the packaged agent guides, README and the
    changelog;
  - the table rows for the new start lines and the audit line;
  - state plainly that a dynamic green is iteration-only.
- New config key `[selection] dynamic` (bool, default true). Render it only
  when false. A doctor/config upgrade note is not required.

### 6.7 Evaluation harness (`scripts/selection_eval.py`, committed)

- Input: a project with a fresh 0.5 store (one `ptest --full`).
- Samples mutation sites by class:
  - `raise` at function entry, which validates dependency completeness;
  - comparison or boolean flip in a function body;
  - module constant change;
  - class attribute change;
  - default-argument change;
  - decorator argument change;
  - import-line change;
  - data-file edit.
- For each mutant, in a scratch git worktree:
  - plan v2 and v1 (0.4.10 rules);
  - ground truth: run, through ptest, the union of the v1 selection and the v2
    selection, or full when v1 is full and affordable;
  - record the failing tests;
  - a baseline run without the mutant marks pre-existing or flaky failures;
  - a **miss** is a test that fails under the mutant, passes in the baseline,
    and was not selected by v2.
- Output: a JSON and a markdown report with misses (classified by section 9's
  residual risks), selection size (v2 / v1 / full), and planning time.
  Deterministic given `--seed`.
- Recording overhead benchmark: the same full run with `dynamic=false` and
  with `dynamic=true`, back to back, three times, reporting the median.

### 6.8 Included fix: nested monorepo child scopes

`monorepo.route_scopes` matches only the first path segment against child
declarations. So a nested child such as `services/control-plane` can never be
targeted (`ptest --full services/control-plane` and
`ptest services/control-plane/tests` both fail with `invalid-config`, while the
message suggests exactly those forms). Match the longest declared child prefix
instead. Add regression tests for nested and sibling children, and for a
child name that is a prefix of another (`services/api` vs `services/api-v2`).

## 7. Negative contracts (must NOT happen)

N1. A test whose recorded dependencies changed is never skipped by the dynamic
    engine, including a dependency recorded in a higher-scope fixture context.
N2. A test without a valid record is never skipped unless the static rule
    proves it unaffected.
N3. An opaque or demoted test is never skipped by dynamic evidence; only the
    static rule may skip it.
N4. A failed or errored test is never skipped by any engine until it passes.
N5. A dynamic or static changed-mode green never records a full baseline,
    `already verified` proof, or last-green full proof, unless the run was
    executed as `--full` (section 5.9).
N6. Recording never changes argv, test outcomes, exit status, stdout/stderr
    (beyond documented ptest lines), or coverage numbers. A recorder failure
    never fails a run.
N7. Records from one project, compatibility fingerprint or policy never
    influence another. Records are never shared across users or machines.
N8. A run whose inputs changed during the run, or whose handoff was incomplete,
    writes no records.
N9. History summaries persisted by 0.5 stay decodable by ptest 0.4.10: no new
    persisted fields, no new persisted reason codes without
    `_PERSISTED_REASON_ALIASES`. A test runs a frozen 0.4.10 field and code
    list over persisted rows.
N10. The audit hook and monitoring callback never raise into project code, and
     never record paths outside the checkout or the contents of any file.
N11. Planning never executes project code: parse only, never import.
N12. The store never grows without bound; over the cap, records are evicted,
     never left to fail the run.
N13. Recording never enables global monitoring events and never re-traces
     library code per test. A suite that passes within its `pytest-timeout`
     limits without recording passes within them with recording on a quiet
     machine (A4).

## 8. Abuse cases (secure-by-spec)

| Axis | Abuse case | Required behaviour / test |
|---|---|---|
| Identity | store, dependency file, or deselect binding pre-created as a symlink or foreign-owned file | refused, never followed; that run falls back to static; private-file checks as in 0.4.10 dumps |
| Authorization | another checkout of a *different* project id writes records | keyed by project id; never read across ids (N7) |
| Tenancy | two worktrees of one project record concurrently | transactional upserts; no lost or torn records; each run replaces only the tests it ran |
| Tenancy | gate worktree on identical code reuses builder records | "no tests affected" only when the compatibility fingerprint and every recorded digest match |
| Input | hostile `co_filename` (`<string>`, paths with `..`, NUL, symlink into checkout, file outside checkout) | dropped; never recorded; never escapes checkout |
| Input | huge dependency output (millions of functions, giant paths) | capped; overflow → opaque or dropped worker, never OOM or crash |
| Input | malformed or truncated dependency file or store row | ignored with a reason; static fallback; never a crash and never a wrong skip |
| Input | node id with brackets, `::`, unicode or newlines in the deselect binding | exact-match deselection; unsafe ids → keep the whole file selected |
| Input | test code tampers with the recorder (unregisters the tool, swallows events) | detected where cheap (tool id ownership check at context switch → opaque); otherwise residual R5, caught by the full gate and the self-audit |
| State | file changes mid-run | no records written (N8) |
| State | interrupted, cancelled or stalled run | no records from it |
| State | store corrupted or hot journal | existing SQLite recovery; else rebuild empty with a reason |
| State | xdist worker crash | its tests unrecorded |
| Exposure | `-v` prints function names and paths | escaped through `render.terminal_text`; JSON gains no per-test dependency data |
| Exposure | `.env` or secret files opened by tests | only the relative path and a *keyed* digest stored; never content |

## 9. Residual risks (documented; covered by the mandatory full gate and the self-audit)

R1 nondeterminism, order dependence, shared external state (DB rows, caches).
R2 dynamic references to changed module-level names (`getattr`, string
   registries, `importlib` by name, SQLAlchemy string relationships) when the
   change is a module-level (skeleton) change.
R3 load-time side effects of an import-line change (the newly imported
   module's import-time effects).
R4 a spawned non-Python binary that runs project code.
R5 test code tampering with the recorder.
R6 `.py` files read as data.
R7 installed-package or C-extension changes not reflected in a lockfile.
R8 behaviour that depends on line numbers (an AST-normalised fingerprint
   ignores pure line shifts).
R9 code that runs in a thread outside the active test's lifetime, attributed
   to whichever context is active.

## 10. Acceptance thresholds (release gate for 0.5.0)

A1 **Safety.** Mutation evaluation on persea_ai `services/control-plane`
   (≥ 150 mutants) and on ptest's own suite (≥ 50 mutants; its static ground
   truth is about 2,900 tests per mutant, so a larger sample would hold the
   shared queue for hours), across all operator classes. Zero misses outside
   R1–R9. Every miss is listed and classified in the report, and any
   unclassifiable miss blocks the release. The harness runs every test it needs
   through the *branch's* ptest (`uv run ptest` in the worktree), which queues
   politely like any other run, and it may take hours.
A2 **Precision.**
   - Function-body mutants: median v2 selection ≤ 20% of the median v1
     selection on (b).
   - On (a), the median v2 selection must not exceed v1. ptest's suite spawns
     Python subprocesses heavily, so it mainly tests safety.
   - All other classes: report only.
A3 **Planning latency.** Warm planning ≤ 1.5 s, cold no worse than 0.4.10, on
   `persea_content_maker_unified/api` (static index part; measured without
   running its suite).
A4 **Recording overhead.** ≤ 15% wall time median on a full run of (a) and of
   (b); coverage totals identical with and without recording.
A5 **Store size.** ≤ 64 MiB at 20k tests (synthetic stress); the eviction
   path is tested.
A6 Integrated `ptest --full` green on the release commit.

## 11. Test strategy (tests-first, through ptest only)

- Unit tests:
  - scope and statement differ: every row of the 5.3 classification;
    formatting-only edits yield no change;
  - name resolver: aliases, `module.attr`, re-exports, star imports;
  - name-propagation fixpoint;
  - per-test decision table: every 5.5 clause, each with a negative twin;
  - store: round trip, concurrent upserts, pruning, eviction, corruption
    fallback, private-file refusals;
  - deselect binding validation;
  - N9 frozen 0.4.10 decode test.
- Real-subprocess bridge tests (pytest serial and xdist):
  - recorded F/M/X/D/opaque for a fixture project with a session fixture that
    calls project code, a lazy import, a data file read, a Python subprocess
    and a non-Python subprocess;
  - outcomes and coverage unchanged with recording;
  - recorder failure paths (tool id taken, cap overflow).
- End-to-end through the CLI:
  - edit one function → only its tests run (node-level);
  - edit a constant → referencing functions' tests;
  - effectful change → static fallback;
  - unrecorded store → static;
  - second checkout on identical code → "no tests affected";
  - failing test always reruns;
  - self-audit miss → demotion line.
- Each abuse case has a test observed failing first (secure-by-spec).
- Evaluation harness runs (section 6.7) produce the A1–A5 numbers committed
  under `docs/research/` and quoted in the changelog.

## 12. Prototype evidence (2026-10-07)

Micro-benchmark (Python 3.13 / 3.14; 2000 synthetic tests × 2000 calls):

| Mechanism | Wall time | Note |
|---|---|---|
| no tracing | 1.27 s / 0.97 s | baseline |
| PY_START + DISABLE + `restart_events()` per test | 1.29 s / 1.14 s | +2% / +18% |
| PY_START callback on every call | 3.7 s / 4.6 s | 3–5× slower; rejected |

Coverage (ctrace, branch) totals are identical with per-test restarts.

Audit `open` events fire for imports (`.py`, `__pycache__`), so the data
filter is required. `subprocess.Popen` and `os.system` events fire as
expected.

Real-suite prototype (2026-10-07). A conftest plugin recorded, per test, the
project functions executed (global PY_START + DISABLE + restart per test),
the data files opened and opacity. Static reach is from the 0.4.10 internals,
with no full_ratio cut-off. The analysis script is
`scratchpad/analyze.py`; the harness in 6.7 replaces it.

| Suite | Tests | Opaque | Static: tests per changed file (median) | Dynamic: tests per changed function (median of per-file medians) | Reduction |
|---|---|---|---|---|---|
| ptest (own suite) | 5,312 | 539 (10%, subprocess-heavy) | 2,890 (54%) | ~340 (6.4%), mostly the opaque floor | ~9× |
| persea_ai control-plane | 1,002 | 0 | 184 (18%) | 12 (1.2%) | ~15× |

Hub files stay hubs dynamically, and that is correct: every test really runs
`core/errors.py`, `orm/repositories/base.py` and `api/app.py`. But typical
service and repository functions drop to single or double digits. The
motivating persea api case (559 of 716 files) has the same hub shape, so a
larger reduction is expected there.

Prototype lessons that shaped section 6.1:
- Global events re-trace library code on every test.
- The ptest run took 367 s against 226 s on a heavily loaded machine (load
  10–13), not a clean A/B. The control-plane run tripped six 1 s
  `pytest-timeout` limits.
- Hence: local events on project code only, the per-test overhead budget, and
  N13.
- The prototype also hit the bridge's hook refusals: `pytest_runtest_protocol`
  and `pytest_sessionfinish` from a registered module are refused. The real
